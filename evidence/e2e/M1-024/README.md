# M1-024 E2E Evidence

`result.json` in this directory is generated by
`Tests/SystemTests/Scripts/M1-024-barrier-client-handshake-fixtures.sh` through
`Tools/Evidence/run_e2e.py`. It records one local, repeatable validation of the
sanitized Barrier client handshake fixture and of the M1-024 evidence package.

## What the run does and does not do

The script is local only. It reads repository files, recomputes digests and
writes `result.json` atomically. It never opens a network connection and never
runs `ssh`, `scp`, `tcpdump`, `dumpcap`, `barrierc` or `barriers`, so running it
does not repeat, re-observe or re-validate the capture. The only external
program it runs is `git`, read-only, to read HEAD and the tracked file list.

The run asserts nothing about Barrier field meaning, message code, message
boundary, endianness or compatibility, and it asserts no Windows result. The
observation boundaries in the fixture are direction runs of the captured byte
stream, not messages.

## Rerun

```bash
make e2e ISSUE=M1-024
python3 Tools/Evidence/validate_evidence.py evidence/e2e/M1-024/result.json
```

`make e2e ISSUE=M1-024` must print `e2e disposition: passed` and `e2e exit: 0`.
Each run replaces `result.json`, so `startedAt` and `endedAt` change while the
checked facts, digests and case list stay the same. A rerun after the recorded
run therefore produces an equivalent document with newer timestamps. The last
green-phase entries in `evidence/issues/M1-024/tests/e2e-validation.json` are
recorded from a real run, and one further rerun then regenerated `result.json`
so the generated document matches the completed package.

## Commit provenance

M1-024 lands in two commits: the implementation commit carrying the eleven
implementation-author Exact Files, then a separate review commit carrying
`independent-review.md`.

`result.json` carries `commit`: the exact repository head of the E2E execution
that produced it. The author-phase evidence files carry something different and
weaker on purpose. `commands.json`, `environment.json` and
`tests/e2e-validation.json` each carry `repositoryHeadAtAuthorRun`, the head the
implementation author ran over while those eleven files were still uncommitted.

The script requires that value to be a full commit id that is an ancestor of, or
equal to, the current head, checked read-only with
`git merge-base --is-ancestor`. It must not require equality: committing those
files moves the head, so an equality rule would make the resulting tree
permanently unable to pass its own gate. Malformed values, values git cannot
resolve, and real commits outside the current history are each rejected and no
result is written.

After root commits the eleven implementation-author Exact Files, the independent
reviewer runs against that implementation commit, creates
`evidence/issues/M1-024/independent-review.md` and records that exact SHA in it.
The reviewer's E2E run regenerates `result.json` against the implementation
commit, before the separate review commit that carries the twelfth file exists.

Negative testing uses a private mutated copy of the fixture directory outside
the repository:

```bash
M1_024_FIXTURE_ROOT=<private mutated copy> \
  bash Tests/SystemTests/Scripts/M1-024-barrier-client-handshake-fixtures.sh
```

That mode validates the fixture pair only, writes no result file and reports
through its exit code. Provenance rules are only reachable in the normal
repository mode, so the provenance mutation checks temporarily mutate a private
copy of an evidence file in place and restore it afterwards.

## Cases

| Case | Meaning |
|---|---|
| `fixture-format` | Closed capture document rules: keys, contiguous sequence, both directions, canonical base64, bounded sizes |
| `fixture-metadata` | Fixture metadata schema rules plus recomputed payload digest and byte length |
| `toolchain-lock` | `M1-CAPTURE-TOOLCHAIN-001` is LOCKED and every pinned version matches |
| `evidence-inputs` | Required M1-024 evidence files exist, parse, name an author-run head that is an ancestor of or equal to the current head, and agree with the current fixture digest |
| `privacy-scan` | Identifying-pattern scan over every Exact File present in the tree and over the decoded payload bytes; the eleven implementation-author files are required, and `independent-review.md` joins the scan once the reviewer has created it |
| `nonclaim-scan` | No document line asserts wire semantics, and no line asserts a Windows result |
| `raw-capture-exclusion` | No tracked path is a raw capture, and the fixture directory holds only its two files |

Any failing check exits non-zero and writes no result; a missing fixture or
evidence input fails closed and is never reported as `not_executed`.

## Review status of the artifacts

`artifacts[].reviewStatus` is `reviewed` because the capture producer reviewed
and verified the sanitization before the bytes were placed in the repository
working tree. That is
not the M1-024 independent review. `evidence/issues/M1-024/independent-review.md`
is authored only by a reviewer who is neither the capture producer nor the
implementation author, and it is absent until that reviewer writes it.
